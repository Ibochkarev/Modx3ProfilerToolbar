# Работа с Frontend Dev Toolbar

Краткое руководство по включению тулбара и интерпретации метрик.

## Включение

1. В системных настройках включите **modx3profilertoolbar.enabled** и **modx3profilertoolbar.frontend_toolbar**.
2. Убедитесь, что вы залогинены в Manager (сессия в контексте `mgr`) — тулбар показывается только при входе в админку.
3. Откройте любую страницу сайта в контексте **web**.

В правом нижнем углу появится панель Dev Toolbar. Подписи локализованы (ru/en/uk) из лексиконов MODX.

## Как собирается статистика

Вся статистика собирается **на сервере** во время обработки запроса; отдельного AJAX-запроса за метриками нет.

1. **Старт** (событие **OnMODXInit**): плагин создаёт ProfilerService, вызывается `start()` — генерируется `request_id`, регистрируются профайлеры (SQL, snippet/plugin/chunk), подменяется парсер для учёта тегов. При **OnHandleRequest** / **OnLoadWebDocument** / **OnWebPagePrerender** профайлер записывает начало и конец этапов.

2. **Сбор во время запроса**: SQL перехватывается через PDO-профайлер; сниппеты, чанки и плагины — через обёртки парсера. Данные попадают в ProfilerService (events, tags, sql).

3. **Стоп** (в **OnWebPagePrerender**): вызывается `stop()` — CollectorService формирует структуру трейса (metrics, events, tags, sql), AnalyzerService считает Advisor и performance_score.

4. **Вывод на фронт**: если контекст `web` и пользователь залогинен в Manager, ToolbarService в методе `inject()` формирует объект для тулбара (`metrics`, `slow_components`, `timeline`, `sql`, `lexicon`), сериализует его в JSON и вставляет перед `</body>` тег `<script>window.modx3profilertoolbarToolbarData = {...};</script>` и подключение `toolbar.js`. Скрипт читает `window.modx3profilertoolbarToolbarData` и отображает панель.

Данные в тулбаре относятся к **текущему** запросу и уже «зашиты» в HTML в момент отдачи страницы.

## Свернутое состояние

Компактная строка с основными метриками:

```
⏱ 412 ms   🧠 42 MB   🧩 18 сниппетов   🛢 34 SQL
```

| Символ | Метрика |
|--------|--------|
| ⏱ | Общее время выполнения запроса (мс) |
| 🧠 | Пиковое использование памяти (MB) |
| 🧩 | Количество выполненных сниппетов |
| 🛢 | Количество SQL-запросов |

Клик по панели разворачивает полную панель с вкладками.

## Развёрнутое состояние

### Вкладка: Overview

Метрики с цветовой индикацией (время в миллисекундах):

- **Общее время (Total time)** — полное время ответа запроса.
- **TTFB** — Time To First Byte.
- **PHP** — время выполнения PHP-кода.
- **SQL** — время, затраченное на SQL-запросы.

Ниже: **Время запросов (Query time)** в секундах и **Источник (Source)** — `database` или `cache`.

**Интерпретация цветов:**

- 🟢 **Зелёный** — хорошо (< 200 мс).
- 🟡 **Жёлтый** — приемлемо (200–500 мс).
- 🔴 **Красный** — требуется оптимизация (> 500 мс).

### Вкладка: Slow Components

Топ самых медленных компонентов: Snippet/Chunk/Plugin с временем в мс и пометкой cached/uncached. Используйте как подсказки для оптимизации.

### Вкладка: Timeline

Горизонтальный waterfall событий MODX: длина полосы пропорциональна времени.

### Вкладка: SQL

Список SQL-запросов с временем, количеством вызовов и пометкой **⚠️ Possible N+1** при подозрении на N+1.

## Если тулбар не появляется

1. Проверьте **modx3profilertoolbar.enabled** и **modx3profilertoolbar.frontend_toolbar**.
2. Убедитесь, что вы в контексте **web**.
3. Проверьте, что залогинены в Manager (тулбар доступен только при сессии в контексте mgr).
4. Убедитесь, что плагин Modx3ProfilerToolbar включён и привязан к событиям (OnMODXInit, OnHandleRequest, OnLoadWebDocument, OnWebPagePrerender).
5. Проверьте консоль браузера на ошибки (блокировка скрипта toolbar.js или отсутствие `window.modx3profilertoolbarToolbarData`).
